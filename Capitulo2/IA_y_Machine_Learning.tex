\section{Fundamentos del aprendizaje automático (ML)}

En los últimos años, la IA se ha vuelto parte de la cultura popular de nuestra sociedad y temas como el aprendizaje automático, ha alcanzado un hito en popularidad bastante marcado, esto debido a dentro de la misma inteligencia artificial esta es una de las ramas más destacadas, permitiendo a un sistema aprender de manera automática patrones a partir de datos y con los mismos poder realizar predicciones precisas a partir de los datos dados. En pocas palabras, el Machine Learning como nos referiremos al aprendizaje automático de ahora en adelante, busca que los sistemas informáticos "aprendan" de las experiencias de los datos, esto sin ser programados explícitamente para llevar acabo una tarea en especifico. 

Sin embargo, pese a la reciente popularidad de la inteligencia artificial, que de ahora en adelante nos referiremos a ella como IA, y el creciente interés del publico en general por todos los temas concernientes a la misma, es un hecho que desde mediados del siglo pasado se comenzó a gestar el desarrollo de la IA, y desde inicios de los 2000 diversas y discretas aplicaciones de la IA acompañaron la vida de las personas, desde integraciones en video juegos hasta motores de búsqueda como Google. 

Una de las definiciones que mejor describe el machine learning es la citada por \cite{Mitchell1997}:

\begin{quote}
	\small
	A computer program is said to learn from experience E with respect to some task T 
	and some performance measure P, if its performance on T, as measured by P, improves 
	with experience E.
	
	\begin{flushright}
		—\textit{Tom Mitchell, 1997}
	\end{flushright}
\end{quote}

A manera de ejemplo para poder entender como funciona el Machine Learning \cite[p. 4]{2017Géron} explica esta definición usando como ejemplo el filtro de correos electrónicos de spam, la cual es una aplicación del machine learning, dice que el sistema puede aprender a marcar spam a partir de ejemplos de correos electrónicos spam (por ejemplo, marcados por los usuarios) y ejemplos de correos electrónicos normales (no spam, también llamados "ham"). Los ejemplos que el sistema utiliza para aprender se denominan conjunto de entrenamiento. Cada ejemplo de entrenamiento se denomina instancia de entrenamiento (o muestra). En este caso, la tarea $T$ consiste en marcar el spam para los correos electrónicos nuevos, la experiencia $E$ son los datos de entrenamiento y es necesario definir la medida de rendimiento $P$; por ejemplo, se puede utilizar la proporción de correos electrónicos correctamente clasificados.

Esta explicación se puede extender de igual forma al problema central de esta tesis, el churn, pensemos que tradicionalmente una empresa tiene ciertas reglas de negocio para considerar a un cliente como perdido o Churn, más tarde ahondaremos en las posibles definiciones de dichas reglas, por el momento supongamos que una empresa define n cantidad de reglas para clasificar a sus clientes como churn y no churn, si dichas reglas se trasladan a un software el resultado sería algo muy similar al diagrama \ref{fig:TraditionalApproach}.

El problema de este enfoque tradicional es claro, una vez que se identifiquen las áreas de oportunidad en las reglas de negocio se tendrían que hacer adecuaciones en las mismas, quitar o añadir nuevas, principalmente esto ultimo paso va consumir mucho tiempo en mantenimiento y aumenta enormemente la complejidad de dichas validaciones, ya que por cada error cometido por el sistema se tendrían que estar añadiendo más y más reglas de negocio para obtener clasificaciones lo más certeras. 

En cambio, si esta misma tarea la realizamos usando un enfoque de Machine Learning la trazabilidad cambia totalmente, ya que el algoritmo de ML (Machine Learning) aprende de manera automática las caracterizaras que son buenos predicadores de clientes churn y no churn, al igual que el sistema esta mucho más acotado, es más fácil de entender y, muy probablemente, sea más preciso. El como abordar el Machine Learning este problema lo podemos ver más claramente en el diagrama \ref{fig:MLapproach}, donde notamos que en esta ocasión en flujo del proceso ya no depende de reglas de negocio establecidas manualmente, esta vez son los datos históricos quienes alimentan al modelo. Este aprende por sí solo las relaciones complejas entre las variables que describen a los clientes, permitiendo generalizar a nuevos casos con mayor precisión.

En este enfoque, los datos se convierten en el suministro más valioso, una vez que nuestro modelos este entrenado, se puede evaluar su rendimiento utilizando métricas objetivas del rendimiento, como la exactitud, la precisión, etc. Si el rendimiento no es el esperado, se pueden analizar los fallos, ajustar el modelo o incluso recolectar nuevos datos, para así reiniciar el bucle de aprendizaje.

Algunas de las ventajas del enfoque de Machine Learning son la \textit{escalabilidad}, ya que los modelos pueden adaptarse sencillamente a nuevos datos sin tener que rescribir reglas de negocio de forma manual. Otra ventaja es \textbf{capacidad para detectar patrones complejos}, esto ya que los algoritmos de pueden reconocer correlaciones no lineales y dependencias que a simple vista sería muy difíciles de identificar mediante validaciones fijas. Por ultimo y no menos importante, \textbf{la capacidad de mejorar continuamente} el ciclo iterativo nos permite evolucionar progresivamente nuestro sistema esto conforme van cambiando ciertos patrones de comportamiento de los clientes. De tal suerte que aplicar modelos de Machine Learning en la predicción del churn no solo representa una mejora tecnológicamente hablando, sino también un cambio de paradigma en la manera en que las empresas pueden combatir el abandono de clientes.  

\section{Aprendizaje Supervisado}

Ya hemos abordado una pequeñas introducción al aprendizaje automático o machine learning, y como usando esta perspectiva podemos ayudarnos para resolver distintos problemas de la vida cotidiana en múltiples ámbitos, entre ellos el empresarial, además su implementación puede ser más practica, escalable y fácil de mantener a lo largo del tiempo. Sin embargo, es necesario saber que el machine learning es un tipo de inteligencia artificial, y aun que anteriormente hemos mencionado con cierta naturalidad el concepto de inteligencia artificial es necesario dar un par de definiciones para entender mejor este concepto, según \citealp{Russell2020}:

%% Cambiar al idioma original.

\begin{quote}
	\small
	"La inteligencia artificial es el estudio de los agentes que reciben percepciones del entorno y realizan acciones."
	
	\begin{flushright}
		\citet[p. 1]{Russell2020}
	\end{flushright}
\end{quote}

Otra definición bastante interesante es la dada por \citealp{luger2005ai}:

\begin{quote}
	\small
	"La inteligencia artificial es el estudio de los mecanismos computacionales para la percepción y el razonamiento, que pueden imitar la inteligencia humana."
	
	\begin{flushright}
		\citet{luger2005ai}
	\end{flushright}
\end{quote}

De tal forma que si hilamos estas definiciones con la antes dada para el machine learning, podemos darnos cuenta que es un caso particular de la inteligencia artificial, ya que el machine learning busca brindar a las maquinas la capacidad de aprender a partir de datos, y aunque el propósito no sea emular el razonamiento humano, la importancia del machine learning reside en poder capturar patrones y predecir resultados futuros con cierta medida de la incertidumbre. Este mismo tiene varios subtipos o ramas, las cuales son:

\begin{itemize}
	\item \textbf{Aprendizaje supervisado}
	\item \textbf{Aprendizaje no supervisado}	\item \textbf{Aprendizaje semi-supervisado}
	\item \textbf{Aprendizaje por refuerzo}
	\item \textbf{Aprendizaje por lotes y en línea}
\end{itemize}

Y de la misma forma en que el machine learning hace parte de la inteligencia artificial como una rama dentro de esta disciplina, así como todos los tipos de aprendizaje automático que mencionamos anteriormente, el diagrama \ref{fig:IA_ML_Tipos} ejemplifica perfectamente la jerarquía entre inteligencia artificial, machine learning e incluso el deep learning o aprendizaje profundo que es un tipo de aprendizaje automático, una de las definiciones más famosas es la siguiente:

\begin{quote}
	\small
	"Deep learning is a class of machine learning algorithms that use multiple layers to progressively extract higher-level features from the raw input."
	
	\begin{flushright}
		\citet{lecun2015deep}
	\end{flushright}
\end{quote}

De hecho uno de los diferenciadores principales entre el deep learning y los demás tipos de aprendizaje automático es la que se menciona en la definición anterior, los modelos de deep learning, los cuales suelen ser Redes neuronales, minimizan la intervención humana a la hora de selección de características, lo que permite una mayor automatización y eficiencia en problemas de complejidad mayor.

Podríamos continuar hablando acerca de todas las ramas en las que se especializa la inteligencia artificial sin embargo no es el propósito de este trabajo. Pero algo que si esta dentro del alcance de este trabajo es el aprendizaje supervisado, el cual es una de las ramas más importantes dentro del aprendizaje automático y la base principal para elaborar modelos predictivos como los que podríamos usar para predecir y explicar el churn. 


En términos generales este enfoque es muy parecido al ejemplo del diagrama \ref{fig:MLapproach}, entrenamos nuestro modelo (sistema) con datos históricos como ejemplos de entrada, cada uno de los cuales esta asociado a una salida esperada. El objetivo es que este modelo aprenda las distintas relaciones que pudieran existir entre las diferentes variables que se le presenten estas asociadas a un resultado, y este mismo sea capaz de predecir salidas de forma correcta a datos sin un resultado definido.

En términos matemáticos el sistema buscar aprender una función que explique la relación entre las variables de entrada, el cual común mente es llamado matriz de características o variables explicativas, y la variable objetivo. Este proceso puede expresarse de las siguiente manera:

\begin{micaja2}
	\begin{equation}
		f: \mathbb{R}^{n\times m} \rightarrow \mathbb{R}^n
	\end{equation}
	\label{EC:MapaML}
\end{micaja2}

Donde $ \mathbb{R}^{n\times m} $ representa la matriz de características con $n$ observaciones o filas y $m$ características o columnas, por otra parte $\mathbb{R}^n$ es la variable objetivo o termino dependiente, este mismo es el vector de los valores de salida esperados de orden $n$, además nos referiremos a $f$ como "modelo".

En el caso del Churn cada fila de la matriz $n \times m$ es un cliente, por lo cual tendríamos $n$ clientes con $m$ características, las cuales pueden ser consumo, frecuencia de compra, etc. Similarmente las salidas nos indican si un cliente abandono o no, lo cual se puede representar como un vector $ \mathbf{y} = \begin{bmatrix} y_1 \ y_2 \ \cdots \ y_n \end{bmatrix}$, con$\quad v_i \in \{0, 1\}, \forall i \in {1, 2, \dots, n} $.

El aprendizaje supervisado resuelve distintos tipos de problemas entre los cuales se encuentra los de tipo regresión y clasificación, mismos que podemos ver ilustrados en el diagrama \ref{fig:ZoomAprendizaje}, en esta tesis solo abordaremos en profundidad los problemas de clasificación ya que el churn puede reducirse a eso.

\subsection{Algoritmos de clasificación}

El churn se puede reducir a un problema de clasificación, más en especifico a una clasificación binaria. Los algoritmos de clasificación permiten predecir la pertenencia de una observación a una categoría o clase definida. En el contexto del churn, el objetivo es predecir si un cliente se mantendrá activo o si abandonará la empresa en un periodo determinado.

En el entorno del Machine Learning, un algoritmos de clasificación son esenciales para poder resolver problemas donde el objetivo es asignar una etiqueta o categoría a un conjunto de datos a partir de las características o variables explicativas. Estos algoritmos construyen modelos predictivos que aprenden patrones a partir de ejemplos históricos que ya está etiquetados, a este conjunto de datos solemos llamarlo conjunto de entrenamiento, para después poder clasificar nuevos registros con base en los datos ya aprendidos. Retomando un poco el problema del abandono de cliente, el objetivo es predecir si un cliente continuara o no en una empresa, con lo que se puede representar como una variable binaria, puede ser 1 para los clientes que abandonan y 0 para los cliente que permanecen. 

Existen varios algoritmos de clasificación, cada uno con sus defectos y virtudes, el qué algoritmo escoger depende de múltiples factores entre ellos la naturaleza de los datos, que interpretabilidad queramos darle a nuestro problema e inclusive el costo computacional. En este trabajo vamos a considerar cuatro algoritmos clásicos en el aprendizaje automático y más en especifico en los problemas de clasificación.

Con base a \cite{2017Géron} enuncio el siguiente teorema, que explica lo anterior:

\begin{teorema}[colback=gray!10, colframe=black!40!black, title=Teorema No-Free-Lunch]
	
Sea $\mathcal{F}$ el conjunto de todas las funciones posibles entre un espacio de entrada $\mathcal{X}$ y un conjunto de salidas $\mathcal{Y}$. Si se considera un conjunto $\mathcal{A}$ de algoritmos de aprendizaje supervisado o de optimización que operan sobre $\mathcal{F}$, entonces:

\[
\frac{1}{|\mathcal{F}|} \sum_{f \in \mathcal{F}} \text{Performance}(A_i, f) = \frac{1}{|\mathcal{F}|} \sum_{f \in \mathcal{F}} \text{Performance}(A_j, f) \quad \forall A_i, A_j \in \mathcal{A}
\]

Es decir, el rendimiento promedio de todos los algoritmos es el mismo cuando se consideran todas las funciones posibles. No existe un algoritmo universalmente mejor sin asumir algún conocimiento previo (sesgo inductivo) sobre el problema.
	
\end{teorema}

Este teorema trae una serie de insinuaciones profundas, el hecho de que no exista un modelo de clasificación ``ideal", esto nos obliga a realizar una serie de validaciones rigurosas de forma práctica para determinar el mejor modelo, osea el que se acople mejor a nuestro conjunto de datos en particular. En nuestro caso, para el churn esto se traduce en que diferentes dataset, como los que tengan granularidad por sector, región o productos, etc., pueden necesitar distintos modelos para lograr una buena generalización.


A continuación, se abordara la teoría de los algoritmos utilizados en la predicción de churn, vamos a poner especial foco en sus fundamentos, ventajas, limitaciones y su interpretabilidad. Es importante remarcar que en este trabajo abordaremos el problema de clasificación binaria, el cual es un caso particular de la clasificación múltiple.

La regresión logística es uno de los modelos más clásicos y popularmente usados en la predicción del churn. Este algoritmo nos ayuda a clasificar las observaciones de nuestro conjunto de datos en dos o más categorías. Básicamente deseamos determinar una regla de decisión a partir de n variables y asignar una respuesta que puede tomar dos o más valores. Más aun tomando en cuenta el mapa \eqref{EC:MapaML} podemos derivar la siguiente función:

\[
	f :x\in \mathbf{R}^{n\times m} \rightarrow y^n\in  \{0,1\}
\]

Lo anterior explica la relación que determinaremos con ayuda de los algoritmos de clasificación binaria en general, incluyendo a la regresión logística y los demás modelos que abordaremos en esta tesis. Aun que antes de entrar en materia con la función sigmoide y la regresión logística conviene mencionar retomar un concepto que de hecho es una generalización de la misma regresión logística, este es la regresión lineal simple, osea vamos a asumir que solo tendremos una variable predictora. A continuación enunciaremos la definición del modelo de regresión lineal simple.

\begin{definicion}{Definición: Regresión Lineal simple}
	Un modelo estadístico lineal que relaciona una respuesta aleatoria $Y$ con una variable independiente $x$ es de la forma:
	\begin{equation}
		Y = \beta_0 + \beta_1 x_1 + \varepsilon
	\label{EC:RLineal}
	\end{equation}
	
	Además supondremos que $\mathbb{E}[\varepsilon] = 0$ y por tanto:
	\begin{equation}
		\mathbb{E}[Y|x] = \beta_0 + \beta_1 x
		\label{EC:RLinealAjustado}
	\end{equation}
	
	donde:
	
	- $\beta_0 \in \mathbb{R}$ es el intercepto (o término independiente).
	
	- $\beta_1 \in \mathbb{R}$ es el coeficiente de x.
	
	- $\varepsilon \sim \mathcal{N}(0, \sigma^2)$ representa un término de error aleatorio.
	

	\begin{comment}
			El objetivo del modelo es encontrar los parámetros $\beta_0$ y $\beta_1$ que minimicen el error cuadrático medio (ECM), es decir:
		
		\begin{equation}
			L:\min\sum_{i=1}^N (Y - \beta_0 - x \beta_1)^2
		\end{equation}
		A este procedimiento se conoce como \textit{mínimos cuadrados ordinarios (OLS)}.
	\end{comment}
\end{definicion}

La regresión lineal al igual que la covarianza y el coeficiente de correlación (lineal) de pearson, nos ayudan a determinar y analizar la relación entre dos variables, sin embargo la regresión lineal va más allá porque nos permite medir el grado de asociación entre dos variables, nos permite imitar un modelo que describa la relación entre estas variables, poder predecir el comportamiento de una de ellas a partir de valores de la otra y hacer mejores inferencias sobre la variable de iteres. Pero la importancia de la regresión lineal, en esta tesis, recide en que con ayuda de esta podemos deducir la función logística, y es que ambos comparten un núcleo en común, la ecuación $\beta_0 +\beta_1 x$, aun que la diferencia radica en como la regresión logística adapta brillantemente esta ecuación, lo conecta a través de la transformación "sigmoide", lo cual le permite usar el poder y la simplicidad de un modelo lineal y aplicarlo para resolver un problema de clasificación, a continuación la definición del modelo.



\begin{definicion}{Regresión Logística Binaria simple}
	Dado un conjunto de datos $\mathcal{D}$ con $N$ pares de entrada y etiqueta binaria $(x_n,y_n)$. El modelo de regresión logística es un modelo lineal generalizado que relaciona la probabilidad de ocurrencia de un evento binario \( Y  \) con un predictor $x\in \mathbb{R}^n$ mediante la siguiente ecuación:
	
	\[
	\mathbb{P}(Y = 1 \mid x) = \frac{1}{1 + e^{\left( - (\beta_0 + \beta_1 x) \right)}}
	\]
	
	o equivalentemente, en términos del logit (log-odds):
	
	\[
	\ln\left( \frac{\mathbb{P}(Y = 1|x)}{1 - \mathbb{P}(Y = 1)} \right) = \beta_0 + \beta_1 x
	\]
	
	Aquí, \( \beta_0, \beta_1\) son los coeficientes del modelo. La función logística transforma la combinación lineal de los predictores en una probabilidad dentro del intervalo $[0, 1]$.
\end{definicion}

De forma ilustrativa vamos a ``demostrar'' el modelo logístico a partir de la ecuación logística. El objetivo es modelar la probabilidad de una variable de repuesta binaria, osea la probabilidad de que $Y=1$ dado un predictivo $x$, a esta probabilidad la denotaremos como $\mathbb{P}(Y=1|x)=p(x)\in [0,1]^n$. Si tomamos en consideración la igualdad \eqref{EC:RLineal}, la idea es determinar una función $L(x)$ tal que:

\begin{equation}
	L(x)=\beta_0+\beta_1 x
	\label{EC:Lx}
\end{equation}

Sin embargo, podemos notar que $(\beta_0+\beta_1 x)\in \mathbb{R}^n$, lo cual contradice el rango que necesitamos que tome $p(x)$. Por otra parte si consideramos a \eqref{EC:RLinealAjustado}, el cual suele ser llamado modelo ajustado o determinista, podemos notar que es exactamente igual a \eqref{EC:Lx}. Por otra parte, un resultado que tenemos que tener en cuenta es la función sigmoide, la cual esta definida de la siguiente manera:

\begin{equation}
	\sigma(t)=\frac{1}{1+e^{-t}}=\frac{e^t}{1+e^t}
\end{equation}

Ahora bien, si aplicamos una composición de funciones $\rho ° L$ de tal forma que:

\begin{align*}
	p(x) &= \sigma(L(x)) \\
	&= \sigma(\beta_0+\beta_1 x) \\
	&= \frac{1}{1+e^{-(\beta_0+\beta_1 x)}}
\end{align*}

De esta manera podemos ver la intrínseca relación que existe entre la regresión lineal y la logística, por lo cual este ultimo hereda algunos supuestos y propiedades de la regresión lineal, las cuales son:

\begin{enumerate}
	\item \textbf{Independencia.} Las observaciones son independientes entre sí
	
	\item \textbf{Relación lineal entre los predictores y el LOGIT del resultado. } Se asume que la transformación logit de la probabilidad es una función lineal de las variables predictoras.
	
	\item \textbf{ Ausencia de multicolinealidad.} Las variables predictoras (las "x") no deben estar altamente correlacionadas entre sí. 
	
	\item \textbf{Tamaño de muestra suficientemente grande.} Sí la regresión logística se basa en la estimación por máxima verosimilitud, cuyas propiedades (como la normalidad de los coeficientes) son asintóticas, es decir, se cumplen mejor con muestras grandes. Una regla general es tener al menos 10 eventos (el resultado menos frecuente) por cada variable predictora que se incluya en el modelo.
	
\end{enumerate}

Otro concepto que resulta crucial mencionar es la función de perdida, este concepto esta intimamente relacionado a uno que suele usarse mucho en el campo de la probabilidad, este es la entropía, que en pocas palabras es la medida cuantitativa de de la indeterminación de cualquier variable aleatoria con un número finito de resultados posibles. En nuestro caso nos apoyamos de este concepto para hacer una evaluación del modelo y poder determinar que tan acertadas fueros las clásificaciones con respecto a las observaciones reales, en ocaciones se le llama función de perdida pero también es conocida como función de entropía cruzada binaria, esto nos permite saber que tan ajustado o no esta nuestro modelo a los datos de entrenamiento y asegurar que nuestro modelo generalice bien, en otras palabras es nuestra principal arma para regularizar el sobre ajuste. La función de pérdida de la regresión logística se puede estimar haciendo uso de la estimación por máxima verosimilitud, a continuación mostraremos la definición de dicha función:

\begin{definicion}{Función de Costo con Entropía Cruzada Regularizada}
	Dado un conjunto de datos $\mathcal{D}$ con $N$ pares de entrada y etiqueta binaria $(x_n,y_n)$, donde $y_n\in[0,1]$, y un modelo que predice la probabilidad $\hat{y}_n=\sigma(x_n)$, la función de costo regularizada $J(\beta)$ que se minimiza para encontrar los coeficientes óptimos del modelo 
	beta se define como:
	
	\begin{equation}
		J(\beta) = \left( \frac{1}{N} \sum_{n=1}^{N} l(y_n, \hat{y}_n) \right) + \lambda \cdot R(\beta)
		\label{eq:costo_regularizado}
	\end{equation}
	
	donde el primer término es la \textit{pérdida de entropía cruzada promedio} y el segundo es el \textit{término de regularización}. La pérdida individual $l(y, \hat{y})$ sigue siendo:
	
	\begin{equation}
		l(y, \hat{y}) = -[y \log(\hat{y}) + (1-y)\log(1-\hat{y})]
	\end{equation}
	
	El término de regularización $R(\beta)$ depende del tipo de penalización elegida:
	\begin{itemize}
		\item \textbf{Penalización L2 (Ridge):} $R(\beta) = \frac{1}{2} \sum_{j=1}^{m} \beta_j^2$
		\item \textbf{Penalización L1 (Lasso):} $R(\beta) = \sum_{j=1}^{m} |\beta_j|$
	\end{itemize}
\end{definicion}

Si bien la función de perdida de entropía cruzada por si sola nos ayuda a construir mejores modelos y evitar el sobre ajuste, más adelante hablaremos más acerca de este concepto, una iterpretación que podemos darle es que esta ecuación nos permite encapsula los dos escenarios posibles:
\begin{itemize}
	\item Cuando la clase real es \textbf{positiva ($y=1$)}, el segundo término se anula ($1-y=0$), y la pérdida se simplifica a: $l(1, \hat{y}) = -\log(\hat{y})$.
	\item Cuando la clase real es \textbf{negativa ($y=0$)}, el primer término se anula ($y=0$), y la pérdida se simplifica a: $l(0, \hat{y}) = -\log(1-\hat{y})$.
\end{itemize}

De tal forma que la fórmula nos ayuda medir la discrepancia entre la probabilidad predicha y la etiqueta verdadera, activando el término correspondiente para cada caso. Ahora bien, en la practica no siempre es conveniente minimizar esta función directamente, lo ideal sería no minimizar la función de pérdida directamente, sino hacer uso de una función de costo regularizada y terminos de regularización. 

La formula \eqref{eq:costo_regularizado} nos permite incitar a nuestro modelo a ser más preciso, mientras que el término de regularización $R(\beta)$ lo empuja a ser más simple al penalizarlo los coeficientes más grandes.

Sabiendo esto, la verdadera magia ocurre cuando generalizamos este modelo para añadir más caracteristicas, esta generalización del modelo es clave para resolver más problemas de la vida real, como el churn, donde el comportamiento de un cliente rara vez se explica por un único factor. La definición de este modelo es la siguiente:

\begin{definicion}{Regresión Logística Binaria múltiple}
	
	El modelo de regresión logística es un modelo lineal generalizado que relaciona la probabilidad de ocurrencia de un evento binario \( Y \in \{0, 1\} \) con un conjunto de variables independientes \( x_1, x_2, \ldots, x_k \) mediante la siguiente ecuación:
	
	\[
	\mathbb{P}(Y = 1 \mid x_1, x_2, \ldots, x_k) = \frac{1}{1 + \exp\left( - (\beta_0 + \beta_1 x_1 + \cdots + \beta_k x_k) \right)}
	\]
	
	o equivalentemente, en términos del logit (log-odds):
	
	\[
	\log\left( \frac{\mathbb{P}(Y = 1)}{1 - \mathbb{P}(Y = 1)} \right) = \beta_0 + \beta_1 x_1 + \cdots + \beta_k x_k
	\]
	
	Aquí, \( \beta_0, \beta_1, \ldots, \beta_k \) son los coeficientes del modelo. La función logística transforma la combinación lineal de los predictores en una probabilidad dentro del intervalo \( (0, 1) \).
	
\end{definicion}

Entre otras cosas algunos de los aspectos más valiosos de la regresión logística, y una de las principales causas de su popularidad en diversas disciplinas e industrias al rededor del mundo, es la capacidad para interpretar sus resultados, y sobre todos los coeficientes del mismo. Esto a diferencia de modelos más complejos, nos permite darle una interpretación más directa y versátil. Por ejemplo el coeficiente $\beta_k$ con $k=0, 1, 2,...$ se puede interpretar como una escala de crecimiento aditivo, si $x_k$ aumenta en una unidad, se suma $\beta_k$ al logit, esto si se mantienen contrastantes las demás variables $x_j$ con $j\neq k$, por otra parte el OR (Odds Ratio), que se calcula como $e^{\beta_k}$, si $x$ aumenta en una unidad, se multiplica los odds por el $OR(e^{ \beta_k })$.

Según \cite{james2013introduction} la estimación de los coeficientes $\beta_k$ se hace mediante el método de Máxima Verosimilitud o por su abreviación en inglés MLE (Maximum Likelihood Estimation), el objetivo de este estimador es encontrar los valores de los coeficientes que meximisen la probabilidad de haber observado los datos de entrenamiento tal cual son. 

Pese a la excelente explicabilidad del modelo de regresión logistica, una de sus principales limitaciones es el supuesto de linealidad del logit, se asume que la frontera de desición que asigna a una clase u otra es lineal. Sin embargo, no siempre se cumple directamente este supuesto en problemas del mundo real, en especial el churn, aun que se pueden aplicar transformaciones previas para tratar de cumplir este supuesto, podemos apelar al uso de otros algoritmos que nos brenden mayor fexibilidad.

De hecho el algoritmo hace un aprendizaje basado en instancias, aveces llamado ``aprendizaje perezoso'' o lazy learning, esto quiere decir que, el algoritmo no aprende parametros apartir de los datos de entrenamiento, en cambio memoriza las instancias de formación que posteriormente se utilizan como ``conocimiento'' para la fase predictiva. Esto contrasta con otros tipos de aprendizaje que van construyendo el modelo de clasificación durante la fase de entrenamiento y posteriormente descartan los datos con los que se entreno el modelo, esto una vez que el modelo esta listo, a esto se le suele llamar ``aprendizaje ansioso'' o eager learners y algunos de sus principales exponentes son los modelos basados en redes neuronales o support vector machines

Hay un par de frases que describe a la perfección el modelo ``el que con lobos anda, a aullar se enseña'' o ``dime con quién andas y te diré quién eres'', el principio es sencillo, el algoritmo busca en las cercanias, o espacio, los puntos ``K'' con mayor proximidad de un nuevo dato (de ahí el nombre K vecinos), tales que una vez contados el numero de puntos asignados a cada clase asigna el nuevo dato a la categoria con más vecinos en ella. Por ejemplo si K=5 y 3 de los 5 vecinos más cercanos son clientes ``Churn", el nuevo cliente será clasificado como ``Churn". A continuación mostraremos el algoritmo del modelo de K Nearest Neighborns. Dado un nuevo punto de datos $\mathbf{x_{new}}$ que se desea clasificar, un conjunto de entrenamiento ($\mathbf{X_{train}}$, $\mathbf{y_{train}}$), un número entero K y una métrica de distancia d:

\begin{enumerate}
	\item \textbf{Calcular distancias:} Se calcula la distancia $d(\mathbf{x}_{new}, \mathbf{x}_i)$ entre el nuevo punto y todos los puntos $\mathbf{x}_i$ en el conjunto de entrenamiento.
	\item \textbf{Identificar vecinos:} Se identifican los $K$ puntos del conjunto de entrenamiento que tienen las distancias más pequeñas a $\mathbf{x}_{new}$. Este conjunto de puntos se denomina $\mathcal{N}_K(\mathbf{x}_{new})$.
	\item \textbf{Votación por mayoría:} La predicción de la clase para $\mathbf{x}_{new}$, denotada como $\hat{y}_{new}$, se determina por la clase mayoritaria dentro de sus $K$ vecinos:
	$$
	\hat{y}_{new} = \underset{c \in \{\text{clases}\}}{\text{argmax}} \sum_{(\mathbf{x}_i, y_i) \in \mathcal{N}_K(\mathbf{x}_{new})} I(y_i = c)
	$$
	donde $I(\cdot)$ es la función indicadora.
\end{enumerate}

Según la explicación anterior podemos darnos cuenta que el algoritmo KNN trae consigo dos desiciones fundamentales: la elección del número de vecinos $K$ y la métrica de distancia, el valor de $K$ nos puede ayudar a controlar el equilibrio entre sesgo y varianza, mientras que la distancia nos ayuda a medir la proximidad entre las nuevas observaciones y los grupos de categorias. Por lo cual asegurar la elección del numero de vecinos $K$ y la métrica de distancia $d$ es una decisión cruzial, ya que definen por completo el comportamiento del modelo y su capacidad para generalizar a nuevos datos.

\paragraph{La métrica de distancia:} Como mensionamos anteriormente el concepto de ``proximidad'' o ``similitud'' es la escencia del modelo K Nearest Neighborns, es la forma en que medimos que tan parecidos son las observaciones entre sí y esto se hace haciendo uso la idea de distancia o metrica. Para elegir la metrica adecuada es necesario tomar en cuenta el escalado de las caracteristicas, por ejemplo, si nuestras variables predictoras se encuentran en distintas escalas, ingresos en miles de millones de pesos, antiguedad en meses o cantidad de productos, la variable que tenga la mayor escala dominara el cálculo de la distancia, ensombreciendo la contribución de las demás. Por ende, es una buena practica normalizar o estandarizar los datos entes de aplicar KNN.

Las métricas más comunes son:

\begin{definicion}{Distancia Euclidiana (L2)}
	Dada la existencia de dos puntos, $\mathbf{p} = (p_1, p_2, \dots, p_n)$ y $\mathbf{q} = (q_1, q_2, \dots, q_n)$, en un espacio n-dimensional, la distancia euclidiana se define como la raíz cuadrada de la suma de las diferencias al cuadrado de sus coordenadas correspondientes.
	
	\[
	d(\mathbf{p}, \mathbf{q}) = \sqrt{\sum_{i=1}^{n}(q_i - p_i)^2}
	\]
	
	Esta métrica corresponde a la norma L2 del vector diferencia $\mathbf{q} - \mathbf{p}$.
\end{definicion}

Para comprender esta metrica podemos pensarlo como medir una línea recta, que es la forma más intuitiva que tenemos de medir cosas en la vida real, suele usarse cuando tenemos datos geoespaciales, cuando el conjunto de datos es denso y tenemos pocas dimensiones y cuando las variables predictoras son de naturaleza similar y continuas, ejemplo pesos, alturas, etc. La unica desventaja es que es muy sensible a outliers.

La siguiente distancia es conocida como distancia de Manhattan, distancia del taxista o distancia de la ciudad, a continuación mostramos su definición. 

\begin{definicion}{Distancia de Manhattan (L1)}
	Para dos puntos $\mathbf{p}$ y $\mathbf{q}$ en un espacio n-dimensional, la distancia de Manhattan es la suma de las diferencias absolutas de sus coordenadas. Es la distancia que se recorrería entre dos puntos si solo se permitieran movimientos a lo largo de los ejes.
	
	\[
	d(\mathbf{p}, \mathbf{q}) = \sum_{i=1}^{n}|q_i - p_i|
	\]
	
	Esta métrica corresponde a la norma L1 del vector diferencia $\mathbf{q} - \mathbf{p}$.
\end{definicion}

Esta métrica es conveniente usarla en espacios de alta dimensionalidad, cuando las características son dispares o no tienen correlación aparente, cuando tienes variables muy sesgadas y por lo tanto quieres evitar la sensibilidad a los outliers.

Finalmente tenemos la distancia de Minkowski, la cual es una generalización de las dos anteriores y esta definida de la siguiente manera.

\begin{definicion}{Distancia de Minkowski (Lp)}
	Es una generalización de las distancias Euclidiana y de Manhattan que introduce un parámetro $p \ge 1$. Para dos puntos $\mathbf{p}$ y $\mathbf{q}$ en un espacio n-dimensional, se define como:
	
	\[
	d(\mathbf{p}, \mathbf{q}) = \left( \sum_{i=1}^{n} |q_i - p_i|^p \right)^{1/p}
	\]
	
	Casos especiales de esta distancia son:
	\begin{itemize}
		\item \textbf{p = 1:} Distancia de Manhattan.
		\item \textbf{p = 2:} Distancia Euclidiana.
		\item \textbf{p $\to \infty$:} Distancia de Chebyshev.
	\end{itemize}
\end{definicion}


De igual manera la definición de valor de $K$ en el algoritmo, se debe hacer en el momento de la construcción del modelo, a $K$ se le conoce como hiperparametro\footnote{Suele definirse al hiperparametro como una variable externa al modelo, es decir, no se obtiene apartir de los datos, sino que debemos definir al momento de implementar el algoritmo.}, es importante remarcar que no existe un valor de $K$ que se acople a todo tipo de conjunto de datos, sino que el valor es subyacente a las propiedades del conjunto de datos en cuestión. En general una pequeña cantidad de vecinos baja tendra en consecuencia un bajo sesgo, pero una gran cantidad de vecinos tendra menor variabilidad pero un mayor sesgo, por lo cual elegir el número de vecinos es una tarea primordial.

Un árbol de decisión en un modelo no paramétrico, este algoritmo nos permite predecir el valor de una variable target, es utilizado tanto en tareas de clasificación y regresión, el modelo aprende ciertas reglas de decisión simples deducidas apartir de las características de los datos. Su estructura es la de un arbol jerarquico, muy parecida a la estructura de datos, consta de un nodo raíz, ramas, nodos internos y nodos hojas. Diagramas como \ref{fig:decision_tree_churn_manual} suele ser muy utiles a la hora de explicar como funciona el algoritmo, cada nivel representa una pregunta y las respuestas seran si o no, de tal forma que eventualmente una respuesta te dará una solución al problema inicial. 

Por ejemplo el nodo ``¿Tiempo como cliente $> 24$ meses?'', lo podemos identificar como nodo raíz, es el inicio de nuestro camino, por otra parte los nodos ``¿Promedio de gasto mensual $> \$50$?'' y ``¿Número de productos/servicios contratados $< 2$?'' son nodos internos, mientras que los nodos que se encuentran al mismo nivel que estos ultimos, son nodos hoja, quiere decir que es el una de las salidas de nuestro algoritmo y finalmente una rama es la ruta que se sigue desde el nodo raíz hasta cualquier otro nodo. El proceso que se lleva acabo para la construcción de un árbol de decisión, común mente se llama partición recursiva, este algoritmo es la modular espinal del modelo de árbol de decisión, además que su funcionamiento es fácil e intuitivo. La premisa es simple, los datos se parten repetidamente apoyándose de los datos de entrenamiento para tratar de conseguir las particiones más homogéneas posibles. 

La homogeneidad pese a parecer un concepto trivial, se formaliza a través de la coeficiente de impureza Gini y la entropía, decimos que un nodo es ``puro'', es decir con impureza cero, si todas las muestras que contiene pertenecen a la misma clase. Por lo tanto, el algoritmo estima cada posible partición y selecciona aquella que maximiza la reducción de entropía o la división que tenga la menor impureza de Gini ponderada en los nodos hijos, el coeficiente de Gini se define de la siguiente manera.\footnote{De hecho la definición del coeficiente de impureza de Gini se puede extender a un problema de clasificación multi clase de la siguiente manera $G=1-\sum_{j=1}^{K}p^2_j$. }

\begin{definicion}{Coeficiente de Impureza de Gini (Caso Binario)}
	Sea p la proporción de muestras pertenecientes a una de las dos clases en un nodo. La impureza de Gini (G) para ese nodo se calcula con la siguiente fórmula:
	
	\[ G = 2p(1-p) \]
	
	Alternativamente, si $p_1$ es la proporción de la clase 1 y $p_2$ es la proporción de la clase 2 (donde $p_1 + p_2 = 1$), la fórmula general es:
	
	\[ G = 1 - (p_1^2 + p_2^2) \] 
\end{definicion}


De igual manera, otro concepto que hay que tener en cuenta es como se lleva acabo la selección de las mejores particiones posibles, si lo vemos desde cierto punto de vista podemos hablar de un algoritmo codicioso que busca en cada paso, tener la mejor elección de una partición posible, sin importar que más adelante dicha división sea impura o poco optima, esto se refuerza con la idea de la imposibilidad de tener un árbol globalmente óptimo, es decir, con todas las subparticiones perfectamente homogenizadas, por lo cual este enfoque nos permite darle un giro de tuerca, heuristicamente hablando, al problema de la creación de un árbol de decisión lo más optimizado posible. Según \cite{EstadisticaPracticacd} podemos definir el algoritmo de partición recursiva de la siguiente manera.

\begin{definicion}{Algoritmo de Partición Recursiva Binaria}
	Dado un conjunto de datos o nodo A con una variable de respuesta $Y$ y un conjunto de M variables predictoras $X_j$ con $j=1,2,\cdots,M$, el algoritmo busca de manera codiciosa la división óptima que segmenta a $A$ en dos nodos hijos, $A_izquierda$ y $A_derecha$. Tal que:
	
	\begin{enumerate}
		\item Para cada variable predictora $X_j$:
		\begin{enumerate}
			\item[a] Para cada posible punto de corte $s_j$ de la variable $X_j$:
			\begin{enumerate}
				\item[i] Se genera una partición tentativa dividiendo las observaciones en $A$ en dos subconjuntos: $A_{izquierda}(j, s_j) = \{X | X_j < s_j\}$ y $A_{derecha}(j, s_j) = \{X | X_j \geq s_j\}$.
				\item[ii] Se calcula la impureza de los nodos hijos resultantes utilizando una métrica predefinida (ej. Gini o Entropía para clasificación; SSE para regresión).
			\end{enumerate}
			\item[b] Se selecciona el punto de corte $s_j^*$ que produce la máxima reducción de impureza para la variable $X_j$.
		\end{enumerate}
		\item Se selecciona la variable $X_j^*$ y su punto de corte asociado $s_j^*$ que, entre todas las variables y sus respectivos mejores cortes, ofrezca la máxima reducción de impureza global para el nodo $A$.
		\item El proceso se repite de forma recursiva en los nuevos nodos hijos ($A_{izquierda}$ y $A_{derecha}$) hasta que se satisface un criterio de parada.
	\end{enumerate}
\end{definicion}

Finalmente otra idea que hay que considerar es la detención del crecimiento del árbol o el control de la complejidad de un árbol de decisión, \cite{EstadisticaPracticacd} menciona que a medida que un árbol de decisión crece, las reglas de división se vuelven más detalladas y este pasa de identificar gradualmente ``grandes'' reglas, que identifican relaciones reales y confiables en los datos, a ``pequeñas'' reglas que solamente generan ruido. Entender esto es crucial, ya que en algunos casos permitir el desarrollo desmedido de un árbol de decisión puede acarrear como consecuencia el aprender completamente el conjunto de datos de entrenamiento, lo cual nos llevaría a un problema de sobre ajuste, cosa que queremos evitar preferentemente. Pese a que existen varias formas de podar nuestros arboles de decisión, la practica suele sugerir inclinarse por métodos como la validación cruzada (que más adelante explicaremos) los cuales nos permiten jugar con distintas combinaciones de hiperparametros, en este caso, profundidad máxima de un árbol, el mínimo de divisiones posibles, entre muchos otros. Para que así podamos encontrar el mejor modelo posible.

Para solucionar el problema del sobre ajuste, Random Forest emplea una técnica de ensamble llamada Bootstrap Aggregating, o Bagging. La idea central del Bagging es reducir la varianza de un estimador promediando las predicciones de múltiples modelos entrenados en diferentes subconjuntos de los datos. 

El algoritmo de Random Forest introduce una capa adicional de aleatoriedad al proceso de Bagging, lo que resulta en una mayor diversificación de los árboles y, en general, en un mejor rendimiento.

\begin{definicion}{Algoritmo Random Forest}
	Para un conjunto de entrenamiento con N muestras y M características, se construye un bosque de B árboles de la siguiente manera:
	
	\begin{enumerate}
		\item Para $b = 1, \dots, B$:
		\begin{enumerate}
			\item Se extrae una muestra bootstrap (una muestra aleatoria con reemplazo de tamaño $N$) del conjunto de entrenamiento.
			\item Se construye un árbol de decisión sobre esta muestra. En cada nodo del árbol, en lugar de buscar la mejor división entre las $M$ características, se selecciona un **subconjunto aleatorio de $m < M$ características** y se busca la mejor división solo dentro de ese subconjunto.
		\end{enumerate}
		\item El árbol se crece hasta su máxima profundidad posible sin realizar podas.
	\end{enumerate}
	
	La predicción final para una nueva observación se obtiene agregando las predicciones de los $B$ árboles, generalmente mediante una votación por mayoría para clasificación.
\end{definicion}

Esta doble aleatorización (muestreo de datos y muestreo de características) es la clave del éxito de Random Forest. Asegura que los árboles individuales no estén correlacionados entre sí. Al promediar las predicciones de un gran número de modelos descorrelacionados, el error debido a la varianza se reduce drásticamente, sin aumentar significativamente el sesgo.

Una de las características más valiosas de Random Forest, especialmente para el objetivo explicativo de esta tesis, es su capacidad intrínseca para calcular la importancia de las características (feature importance). Esto se logra midiendo, para cada característica, cuánto disminuye en promedio la impureza (usando el índice de Gini) en todos los árboles del bosque cada vez que esa característica es utilizada para una división. Esto proporciona una métrica cuantitativa y robusta para clasificar qué variables son las más influyentes en la predicción del churn.

\subsubsection{SVM}

Finalmente e igualmente importante tenemos las maquinas de soporte vectorial o SVM por su abreviación en inglés, dicho algoritmo constituye una clase de algoritmo de aprendizaje supervisado que puede abordar problemas de regresión y clasificación, esto desde una perspectiva geométrica y de optimización. Para el caso especifico de la clasificación binaria el objetivo es encontrar, dado un nuevo punto, cuándo este nuevo punto estará en uno de las dos clases, tomando como ejemplo el diagrama \ref{fig:svm_simple}, la idea de para resolver este problema es simple, debemos encontrar una linea tal que nos permita separar ambas clases, azules y rojas, además podemos notar que existe más de una linea que segmenta mejor nuestras clases, por lo cual una de las soluciones para tener la frontera de decisión más adecuada es encontrar la linea con el mejor margen de separación entre clases, es decir, si elegimos la linea de tal manera que la distancia que hay desde dicha linea hasta el punto más cercano de cada clase sea la maxima posible, solo entonces decimos que hemos encontrado una separación optima de las clases. Nuevamente el diagrama \ref{fig:svm_simple} nos permite observar tres posibles lineas de separación para las clases azul y rojo, en este caso la linea amarilla esta más acercada a la clase roja, por lo cual existe más pasibilidad de clasificar como rojo un punto que podría ser azul, lo mismo para la linea verde que esta más cercana a la clase azul, y donde podemos ver mayor distancia de separación es en la linea azul. A continuación realizaremos una pequeña motivación del fundamento matemático que sustenta este algoritmo.

\begin{definicion}{Hiperplano Separador}
	Dado un espacio de m dimensiones, un hiperplano es un subespacio afín de dimensión $m-1$. Para un vector de características $\mathbf{x} \in \mathbb{R}^m$, un hiperplano se define de la siguiente manera:
	
	\begin{equation}
		H = \{\mathbf{x}\in \mathbb{R}^m|\mathbf{w}^T \mathbf{x} + b = 0\}
	\end{equation}
	
	donde $\mathbf{w} \in \mathbb{R}^m$ es el vector de pesos (ortogonal al hiperplano) y $b \in \mathbb{R}$ es el término de sesgo o ``bias'', que determina el desplazamiento del hiperplano desde el origen.
\end{definicion}

En el caso de que nuestros datos sean linealmente separables pueden existir infinitos hiperplanos que puedan clasificar correctamente las clases. La idea es encontrar el máximo margen de separación, una vez más nos auxiliamos del ejemplo para $\mathbf{x} \in \mathbb{R}^2$, pero ahora usaremos como referencia la figura \ref{fig:svm_nonlinear}, en la misma podemos apreciar que el margen de separación del hiperplano esta ``soportado'' por dos puntos remarcados con círculos rojos, a los cuales nos referiremos como $x_{-}$ y $x_{+}$ ya que son representantes de la clase 1 ($-$) y la clase 2 ($+$) respectivamente, los cuales son llamados ``vectores de soporte'', de aquí el nombre del algoritmo, mismos que en teoría deberían ser los únicos definen o ``soportan'' la posición y orientación del hiperplano.

Una vez que definimos de forma teórica el hiperplano de separación y hablamos en rasgos generales del margen de diferenciación entre cada clase, es necesario profundizar un poco más en el concepto del margen duro y para ello necesitamos deducir los criterios de decisión de nuestro modelo. Dado que la ecuación que define hiperplano es $\mathbf{x} + b=0$, podríamos decir por medio de las desigualdades \eqref{eq:decision_bruto}.

\begin{equation} \label{eq:decision_bruto}
	\begin{cases}
		\mathbf{w}^T \mathbf{x} + b \leq 0 & \text{si es de la clase 1} \\
		\\
		\mathbf{w}^T \mathbf{x} + b \geq 0 & \text{si es de la clase 2}
	\end{cases}
\end{equation}

Esto quiere decir que cualquier punto que no este en la frontera de decisión se clasificara de esa manera, sin embargo y como lo relatamos anteriormente, buscamos tener un margen de separación entre clases, por lo cual, la acción más prudente es considerar los margenes en dichas clases, tal y como lo podemos apreciar en las desigualdades \eqref{eq:decision_boundary}, esto nos permite deducir entonces que $y_i(\mathbf{w}^T \mathbf{x} + b)\geq 1$ con $y_i=1$ o $y_i=-1$, lo cual a corto plazo nos permitirá definir la longitud del margen de nuestro clasificador.

\begin{equation} \label{eq:decision_boundary}
	\begin{cases}
		\mathbf{w}^T \mathbf{x} + b \leq 1 & \text{si es de la clase 1} \\
		\\
		\mathbf{w}^T \mathbf{x} + b \geq -1 & \text{si es de la clase 2}
	\end{cases}
\end{equation}

Además hay que tomar en cuenta que las ecuaciones $\mathbf{w}^T \mathbf{x} + b=\pm 1$ definen los margenes de los respectivos vectores de soporte, misma con la que podemos calcular proyección ortogonal del vector $w$ sobre cada vector de soporte, en la figura \ref{fig:svm_nonlinear} vemos que a proyección se denominan $d_{-}$ y $d_{+}$, que se definen de la siguiente manera.


\begin{equation} \label{eq:proyeccion_ortogonal}
	\begin{cases}
		d_-=\frac{\mathbf{x_1} \cdot \mathbf{w}}{\|w\|} \\
		\\
		d_-=\frac{\mathbf{x_2} \cdot \mathbf{w}}{\|w\|}
	\end{cases}
\end{equation}

si también consideramos que los hiperplanos de los margenes satisfacen la siguiente ecuación $y_i(\mathbf{w}^T \mathbf{x}_i + b) - 1=0$, entonces.

\[\mathbf{w}^T \mathbf{x}_i =\frac{1}{y_1}-b\]

De esta manera podemos calcular el margen total domo $d=d_-+d_+$ y haciendo un poco de álgebra llegamos al siguiente resultado.

\begin{equation} \label{eq:margentotal}
	d=\frac{2}{\|w\|}
\end{equation}

El objetivo de este algoritmo es maximizar la distancia de dicho margen, por lo cual simplemente debemos maximizar a \eqref{eq:margentotal}. Lo cual es equivalente a minimizar $\|w\|$, esto siguiendo la idea de que para que una fracción, cuyo denominador es positivo, sea lo más grande posible, necesitamos hacer que su denominador sea lo más pequeño posible. Más aun $\min_{w}\|w\|$ es equivalente al $\min_{w}\|w\|^2$, la razón de buscar dicha equivalencia es porque es más practico encontrar el vector $w$ que minimice a  $\min_{w}\|w\|^2$, con esto eliminamos la posibilidad de trabajar con raíces cuadradas y simplificamos más el calculo de optimización. Una vez hechos los cálculos enunciamos la definición formal. 

\begin{definicion}{Clasificador de Margen Máximo (Margen Duro)}
	Para un problema de clasificación binaria con etiquetas $y_i\in(0,1)$, el objetivo es encontrar el hiperplano $(w,b)$ que maximice el margen, que es $\frac{2}{\|w\|}$. Esto es equivalente a minimizar $\|w\|^2$. El problema de optimización se formula como:
	
	\begin{equation}
		\min_{\mathbf{w}, b} \frac{1}{2} \|\mathbf{w}\|^2
	\end{equation}
	
	sujeto a la restricción de que todas las instancias sean clasificadas correctamente:
	
	\begin{equation}
		y_i(\mathbf{w}^T \mathbf{x}_i + b) \ge 1, \quad \forall i=1, \dots, m
	\end{equation}
\end{definicion}

La demostración de como resolver este problema de optimización lineal sale del alcance de este trabajo, sin embargo nos gustaría remarcar un detalle especial de esta solución y es la belleza y simplicidad con la que se resuelve el problema de encontrar un margen duro, sin embargo entre las limitaciones que podemos encontrar esta el hecho de que esta solución es altamente sensible a los valores atípicos y no funciona si los datos no son perfectamente separables linealmente, situación que mencionamos anteriormente.  

Con el fin de superar la primera de las limitaciones que mencionamos anteriormente, vamos a introducir un método que nos permite tener mayor flexibilidad a la hora de no tener datos linealmente separables, a este método se le llama clasificador de margen suave. Este modelo permite que algunas instancias violen el margen establecido o incluso sean clasificadas erróneamente, esto haciendo uso de una penalización por cada violación. Este equilibrio entre maximizar el margen y permitir ciertos errores se controla mediante un hiperparámetro de regularización.

La forma en que podemos lograr es muy sencilla, utilizando variables de holgura tales como $\xi_n \leq 0$, para cada instancia, la variable $\xi_n$ nos permite calcular el grado de error del margen por parte de la observación n.

\begin{enumerate}
	\item[*] Si $\xi_n=0$, la instancia está correctamente clasificada y fuera del margen.
	\item[*] Si $0 < \xi_n \leq 1$, la instancia está dentro del margen pero aún en el lado correcto del hiperplano.
	\item[*] Si $\xi_n > 1$, la instancia está en el lado incorrecto del hiperplano (mal clasificada).
\end{enumerate}

Explicado esto, ahora enunciaremos la definición formal del clasificador con margen suave, el problema de optimización lineal que implica y las restricciones a las cuales esta sujeto.

\begin{definicion}{Clasificador de Soporte Vectorial (Margen Suave)}
	El problema de optimización se modifica para incorporar las variables de holgura y un hiperparámetro de regularización $C_0$, que controla el balance entre el ancho del margen y el número de violaciones:
	
	\begin{equation}
		\min_{\mathbf{w}, b, \xi} \frac{1}{2} \|\mathbf{w}\|^2 + C \sum_{n=1}^{N} \xi_n
	\end{equation}
	
	sujeto a:
	
	\begin{equation}
		y_i(\mathbf{w}^T \mathbf{x}_i + b) \ge 1 - \xi_n, \quad \xi_n \ge 0, \quad \forall i=1, \dots, N
	\end{equation}
	
	El hiperparámetro $C$ actúa como un "presupuesto" para los errores. Un valor de $C$ grande impone una penalización severa a las violaciones, llevando a un margen estrecho y un modelo más complejo (menor sesgo, mayor varianza). Un valor de $C$ pequeño es más permisivo, resultando en un margen más amplio y un modelo más simple (mayor sesgo, menor varianza).
\end{definicion}

Si embargo tanto el clasificador de margen duro como el de margen suave tienen una complicación, y es que forzosamente necesitan encontrar una frontera de decisión lineal, por lo cual, para manejar relaciones mucho más complejas y no lineales entre las características, emplearemos una de las técnicas más ingeniosas y elegantes del machine learning, el truco del kernel o la función kernel.

Este método toma el nombre del truco del kernel porque se utiliza una función kernel que calcula el producto escalar entre dos vectores en ese espacio de dimensión mayor, evitando así la necesidad de tener que realizar la transformación de forma explicita. Teniendo en cuenta que el algoritmo de optimización de la SVM solo depende de los productos escalares entre los vectores de entrenamiento, podemos remplazar el producto escalar por la función de kernel.

\cite{StatisticalLearning} a manera de ejemplo nos da una acercamiento a la definición formal de la función kernel y a los distintos tipos que podemos emplear de manera practica, por lo cual mostraremos una sinterización a manera de definición formal.

\begin{definicion}{Función de Kernel}
	Una función de kernel $K$ es una función que toma dos vectores en el espacio original, $x_n$ y $x_m$, y devuelve el producto escalar de sus imágenes en un espacio de características de mayor dimensión, $\phi(x_n)$ y $\phi(x_m)$.
	
	\begin{equation}
		K(\mathbf{x}_n, \mathbf{x}_m) = \phi(\mathbf{x}_n)^T \phi(\mathbf{x}_m)
	\end{equation}
	
	Algunos kernels comunes son:
	\begin{itemize}
		\item Lineal: $K(\mathbf{x}_n, \mathbf{x}_m) = \mathbf{x}_n^T \mathbf{x}_m$. Reproduce el clasificador lineal.
		\item Polinomial: $K(\mathbf{x}_n, \mathbf{x}_m) = (\gamma \mathbf{x}_n^T \mathbf{x}_m + r)^d$. Crea fronteras de decisión polinómicas de grado $d$.
		\item Función de Base Radial (RBF): $K(\mathbf{x}_n, \mathbf{x}_m) = \exp(-\gamma \|\mathbf{x}_n - \mathbf{x}_m\|^2)$. Es un kernel muy popular y flexible, capaz de crear fronteras de decisión complejas. El hiperparámetro $\gamma$ controla la "amplitud" del kernel, determinando la influencia de cada vector de soporte.
	\end{itemize}
\end{definicion}


De esta forma podemos concluir que el uso de funciones kernels para encontrar fronteras de decisión más realistas en las SVM nos permite construir modelos con mayor flexibilidad y potencia, que nos permitan capturar patrones no lineales sutiles, lo que convierte a este algoritmo en una herramienta formidable para problemas de clasificación complejos como la predicción del churn. 

\section{Predicción del churn.}

Los algoritmos antes vistos, regresión lineal, K-Nearest Neighbors, Random Forest y Support Vector son el arsenal de herramientas matemáticas con las que vamos a abordar o combatir el problema de la predicción del abandono o churn. \subsection{Definición de \textit{churn}}

De hecho \citet[p. 36]{2020Gold} define el origen de la palabra \textit{churn} en el término \textit{churn rate}, este termino hace referencia a la proporción de clientes que abandonan la empresa en un periodo determinado. 

Más en especifico el \textit{churn} es un estado u estatus que se le da a un cliente habitual de una empresa o servicio cuando este da por terminada la relación comercial, este concepto ha sido acuñado más recientemente por aquellas empresas que prestan servicios de suscripciones, como pueden ser plataformas de entretenimiento digital, proveedores de servicios de telecomunicaciones (internet, telefonía y/o televisión), etc. Sin embargo el \textit{churn} no es únicamente aplicable a este tipo de compañías.

Ya que solo necesitamos que la empresa en cuestión oferte uno o más productos de los cuales tenga consumidores habituales para poder estudiar el \textit{churn} en toda su cartera de clientes y más en especifico poder abordar distintas estrategias para la retención de clientes. 

En general el estudiar el comportamiento de los clientes puede ser un reto distinto dependiendo de la empresa e industria en la cual el científico de datos o analista de datos se encuentre, por lo cual es necesario tener pleno conocimiento sobre las reglas de negocio en cuestión. Ya que cada caso de estudio necesitará de enfoques distintos para poder entender de mejor manera el \textit{churn} y cómo combatirlo.

De hecho ese debería ser el propósito principal de estudiar el \textit{churn}, poder proporcionar una radiografía certera sobre el comportamiento de los clientes en una empresa, esto eventualmente permitirá a los líderes dentro de la organización poder tomar decisiones basadas en datos, y es tarea del científico de datos proveer la información lo más clara y precisa posible.

\subsection{Determinar el estado de un cliente: \textit{churn} o no Churn}

El concepto de abandono, el estado como tal, debemos trasladarlo a una bandera o etiqueta que se pueda asignar a cada cliente, recordemos que esta misma es la variable objetivo de nuestros modelos de clasificación anteriormente vistos, misma que se podría definir como $y\in {0, 1}$. La forma de otorgar dicha etiqueta a los clientes debe es inherente al negocio o empresa en el que se desea implementar este caso de uso, de hecho podemos decir que hay dos formas en que se puede asignar esta bandera, un churn explicito e implícito.

El primer caso, churn explicito, es característico de negocios enfocados en suscripciones o cobros de servicios en especifico, tales como telecomunicaciones, SaaS, tarjetas de crédito o departamentales, servicios de streaming, etc. En este escenarios, el cliente puede realizar una acción en especifico que puede ser claramente medible para dar por finalizada la relación comercial con la empresa en cuestión, esto puede ser cancelar un contrato, cerrar una cuenta o inclusive no renovar una suscripción. En este caso la definición de la variable objetivo es más clara, si el cliente rompe el vinculo comercial con la empresa en automático se clasifica como churn, osea $y=1$, en el caso contrario, $y=0$. Regularmente en estos casos el analista o científico de datos a cargo no necesita hacer ninguna operación adicional, ya que en los negocios antes descritos, se esperaría lleven una medición de este estado.

\subsection{Metricas y causalidad del \textit{churn}}

Una vez que se determino de mamera exitosa la variable \textit{target} que vamos a modelar, podemos estudiar un poco más a fondo algunos KPI's que se desprenden de dicha variable y que nos permitirán sacar más jugo a nuestro análisis. El hecho de poder etiquetar a los clientes nos permite cuantificar la salud de nuestra cartera de clientes y medir el impacto financiero del abandono de los clientes a través de KPI's clave.

Una de las métricas clave que podemos intuir casi de manera inmediata es el \textit{churn rate} o CCR (por sus siglas en inglés \textit{customer churn rate}), es un kpi en escala de porcentaje que nos permite cuantificar la salud de la cartera de clientes y preever el impacto que monetario que podría conllevar el abandono de clientes, a continuación enunciamos la definición. 

	\begin{definicion}{Tasa de Abandono (Churn Rate)}
	La Tasa de Abandono es el porcentaje de clientes que una empresa pierde durante un período de tiempo específico. Se calcula de la siguiente manera:
	
	\[
	\text{CCR} = \left( \frac{\text{Número de Clientes Perdidos en el Período}}{\text{Número Total de Clientes al Inicio del Período}} \right) \times 100
	\]
\end{definicion}

Un CCR alto es una señal de alerta que puede indicar problemas con el producto, el servicio al cliente o la estrategia de precios. Otra métrica que podemos calcular casi por consecuencias del churn rate es el retention rate que es complemento del CCR, que se calcula de la siguiente manera $CRR=100\%-CCR$, donde CRR significa \textit{Customer Retention Rate}, esto nos ayuda a medir el porcentaje de clientes que la empresa a logrado mantener durante un periodo en especifico.

Otra métrica que nos sera de mucha utilidad será el tiempo de vida del cliente o \textit{Customer Lifetime Value} o CLV, es una métrica predictiva que nos ayuda a estima el valor financiero total, ya sea en ingresos o beneficio neto, que un cliente aportará a una empresa durante la duración completa de su relación comercial.

A diferencia de las métricas transaccionales que se centran en compras individuales, el CLV adopta una perspectiva prospectiva, cuantificando la rentabilidad a largo plazo de un cliente. Una formulación simplificada, pero ampliamente utilizada, para su cálculo se basa en tres componentes clave:

\begin{definicion}{Valor del Tiempo de Vida del Cliente (CLV)}
	El valor del tiempo de vida del cliente aportara a una empresa se calcula de la siguiente manera:
	
	\[
	\text{CLV} = (\text{VMP} \times \text{FC}) \times \text{VPC}
	\]
	
	donde:
	\begin{itemize}
		\item \textit{Valor Monetario Promedio (VMP):} Es el valor promedio de una transacción de un cliente.
		\item \textit{Frecuencia de Compra (FC):} Es el número promedio de transacciones que realiza un cliente en un período de tiempo definido (ej. un año).
		\item \textit{Vida Promedio del Cliente (VPC):} Es la duración esperada de la relación con el cliente, la cual está inversamente relacionada con la Tasa de Abandono (Churn Rate), es decir $\text{VPC} = \frac{1}{\text{CCR}}$
	\end{itemize}
\end{definicion}

En conjunto todas estas métricas, junto a un modelo de clasificación que nos permitan realizar inferencias sobre el universo de clientes que se vaya a estudiar nos permitirá evaluar constantemente el comportamiento de nuestros consumidores y poder emplear diversas estrategias para contrarrestar posibles efectos adversos o impulsar el crecimiento de la empresa en cuestión.

\subsection{Inteligencia Artificial Explicable (XAI)}

Como pudimos observar en secciones anteriores, a medida que los modelos de machine learning se vuelven más enrevesado y potente, con frecuencia se convierte también en un proceso de caja negra, es decir la transparencia con la que se puede entender que tomen ciertas decisiones se vuelve cada vez más opaca, modelos de ensambles como Random Forest o descenso del gradiente son ejemplos perfectos de esto. De la necesidad de ligar la mayor precisión posible de nuestros modelos y dar la mejor inalterabilidad factible es que se dio origen al campo de la inteligencia artificial explicable o XAI.

Esta naturaleza de caja negra se da porque, a diferencia de un modelo interpretable como los antes mencionados, la logica interna de algunos modelos es mucho más compleja y en muchos casos resulta bastante inteligible para un ser humano. De tal manera que debemos debatirlos en un dilema fundamental de la ciencia de datos: elegir interpretabilidad y precisión. Para problemas con un nivel de importancia elevado como lo es el Churn, tener la suficiente certeza de que las predicciones que hagamos son las más acertadas posibles, en este punto el saber cuál cliente va abandonar no es información suficiente para tomar decisiones de forma segura, además de esto entender por qué el modelo llega a esas conclusiones se vuelve una tarea crucial.

Es aquí donde el campo de la inteligencia artificial explicativa (o XAI por sus siglas en inglés) surge, XAI no es una metodología, sino un conjunto de técnicas y una sub rama  de estudio dedicado a desarrollar algoritmos que nos ayuden a encontrar explicaciones fieles y comprensibles sobre cómo los modelos de Machine Learning toman sus decisiones. 

Los objetivos del XAI son; generar confianza y transparencia, permitir que los responsables de negocio puedan validar los resultados del modelo, aseguremos que no se basa en artefactos o sesgos espurios de datos, así como permitir la acción, es decir proporcionar insights accionables, en este contexto, una explicación de XAI debe identificar los "impulsores" del abandono para un cliente especifico, permitiendo al negocio diseñar estrategias de retención personalizada y efectiva.

Además debemos remarcar que hay dos técnicas de XAI pueden clasificarse en varias dimensiones por así decirlo, que son; global, es una explicación que describe el comportamiento promedio del modelo en conjunto (de forma global), local, que es el razonamiento de una única predicción, agnóstico al modelo, estas técnicas funcionan para cualquier tipo de modelo, especifico, que esta diseñada especialmente para un modelo (por ejemplo Gini Importance para árboles).

En esta sección exploraremos las formas de interpretabilidad más importantes para nuestro problema, en este caso comenzaremos con el nivel más fundamental de explicación global: que es la selección de características.



\subsubsection{Importancia de características}

La interpretabilidad global buscar responder una pregunta ¿Qué características son las más importantes para las predicciones del modelo? Poder contestar a esta pregunta se vuelve una tarea crucial para validar si el modelo ha aprendido patrones que hagan sentido con el conocimiento del negocio. Estos análisis se puede realizar a priori o post hoc.  

\subsubsection[Importancia de características]{Análisis de Poder Predictivo a priori con Información Mutua}

En la vida cotidiana, los conjuntos de datos pueden contener cientos de características, incluso miles en especial para problemas como el análisis de imágenes médicas o conducción autónoma, en casos como estos y el churn incluir variables que generen ruido no solo incrementa el esfuerzo computacional necesario, sino que también puede mermar el rendimiento del modelo con un posible sobre ajuste. Por tanto uno de los pasos cruciales es es la selección de características, es un proceso para identificar y mantener solo las variables con mayor poder predictivo.

En esta ocasión usaremos un método de filtrado univariado evaluando cada una de las características individualmente respecto a la variable \textit{target}, la forma que haremos este filtrado sea usando como criterio la métrica de \textit{información mutua}, esta mide la dependencia entre dos variables, es decir se cuantifica la reducción de incertidumbre sobre la variable objetivo que se obtiene al conocer el valor de una característica. La diferencia entre el criterio de información mutua y el coeficiente de correlación es que este ultimo solo detecta relaciones lineales, mientras que el criterio de información mutua puede captar cualquier tipo de relación, incluso las no lineales. Previo a la definición formal, vamos a introducir el concepto de Entropía de Shannon.

\begin{definicion}{Entropía de Shannon}La entropía $H(Y)$ de una variable aleatoria discreta $Y$ es una medida de su incertidumbre promedio. Se calcula como:\[ H(Y) = -\sum_{y \in \mathcal{Y}} p(y) \log(p(y)) \]
	
	donde $\mathcal{Y}$ es el conjunto de todas las eventos posibles y $p(y)$ es la probabilidad de que ocurra la clase $y$. 
\end{definicion}

Cuando hablamos de eventos entienda como las clases o valores de la variable en turno, en el caso de la variable \textit{target} puede ser churn o no churn. La entropía condicional $H(Y|X)$, mide la incertidumbre promedio que queda sobre $Y$ después de que hemos observado la característica $X$. La información mutua es la diferencia entre nuestra incertidumbre original y la incertidumbre restante. 

\begin{definicion}{Información Mutua (Mutual Information)}La información mutua $I(X; Y)$ entre dos variables aleatorias $X$ y $Y$ se define como la reducción en la incertidumbre de $Y$ gracias al conocimiento de $X$:\[ I(X; Y) = H(Y) - H(Y \mid X) \]
	
	Un valor de $I(X; Y) = 0$ significa que las variables son independientes, mientras que un valor alto indica una fuerte relación predictiva.
\end{definicion}

Podemos usar la información mutua como función de puntuación y realizar un análisis de poder predictivo a priori, de tal manera que el filtrado y selección de aquellas características que son teóricamente más informativas para la construcción de nuestros modelos es más simple, lo cual nos podría ayudar bastante a reducir la dimensional de nuestro modelo previo a su fase de entrenamiento.

\subsubsection[Importancia de características]{Importancia de Características Post-Hoc}

Ahora bien, una vez que nuestro modelo ya ha sido entrenado, podemos utilizar técnicas alternativas para inspeccionar el comportamiento global de nuestras variables, en este caso podemos hablar de dos formas de inspeccionar nuestras variables, una forma particular o inherente al modelo y otra global, es decir un método que podríamos aplicar a cualquier modelo independientemente de la naturaleza del mismo. 

Sobre los métodos intrínsecos, sabemos que algunos modelos nos dan la posibilidad de tener cierta facilidad en la interpretabilidad  de forma nativa. En el caso de la regresión logística, si tomamos los valores que tienen los parámetros de la ecuación y los estandarizamos podremos indicar la importancia de cada característica, por otro parte y como lo mencionamos con antelación, en los ensambles de árboles como Random Forest, la reducción Media de la Impureza o la importancia de Gini nos permite medir el valor esperado de la contribución de cada característica, para purificar los nodos de cada árbol. 

Por otra parte, el enfoque por permutación, el cual dicho sea de paso es un método agnóstico al modelo, ofrece mayor potencia y fiabilidad. Su funcionamiento es el siguiente; después de entrenar el modelo y medir su rendimiento, para cada característica $j$, tomamos todos los valores en el conjunto de validación y realizaremos una permutación de forma aleatoria, esto con el objetivo de romper su relación con la variable objetivo, volvemos a evaluar el modelo con este conjunto de datos alterado, finalmente la caída en el rendimiento de la variable $j$-sima se considera como la importancia, de tal manera que si el rendimiento decae drásticamente, significa que el modelo dependía fuertemente de ella.

Sin embargo no es el propósito de esta tesis quedarnos solo con estos métodos globales, ya que aun que son excelentes para validar y entender las tendencias generales de nuestros modelos, nos ayudan muy poco a explicar las inferencias que hace el modelo, esto cobra más relevancia cuando tratas de explicar por que se clasifico a un cliente en particular como churn o no churn. Para tareas de este estilo requerimos métodos de explicación local.

\subsubsection{SHAP}

Ahora bien, SHAP o SHapley Additive exPlanations por sus siglas en inglés es un método que unifica las predicciones individuales de cualquier modelo de machine learning, fundamental en la teoría de juegos, más en especifico guarda una intrínseca relación con los valores de Shapley. Estos valore deben su nombre a Lloyd Shapley quien fue un ilustre matemático y economista estadounidense galardonado con el premio nobel de economía en 2012 junto con Alvin E. Roth por sus contribuciones a la teoría de las asignaciones estables y el diseño de mercados. Shapley realizo múltiples aportaciones  a la teoría de juegos cooperativos, sobre todo estudiando cómo individuos que colaboran en coaliciones deberían repartirse de manera justa las ganancias resultantes de su cooperación.

La pregunta fundamental que Shapley buscaba responder era: ``En un juego cooperativo donde varios jugadores colaboran para obtener una recompensa total, ¿cómo debemos repartir esa recompensa de manera justa entre ellos, considerando que algunos pudieron haber contribuido más que otros'' \citep{Shapley1953}.

Años más tardes, \citet{lundberg2017unified} tuvieron la perspicacia de conectar este problema económico con el aprendizaje automático. Propusieron una analogía directa; el juego podemos tomarlo como la predicción para una instancia  especifica, la recompensa o ganancia total puede ser la diferencia entre la predicción actual del modelo pra ea instancia, $f(x)$, y la predicción promedio del modelo obre todo el conjunto de datos, es decir $E[f(x)]$ y finalmente los jugadores son las características o variables del modelo que cooperar para generar una predicción.  Bajo este entendido, explicar una predicción (explicación local) se convierte en un problema de repartición justa, es decir, ¿cuánto ``crédito'' o ``culpa'' merece cada característica por mover la predicción desde el valor promedio hasta el valor final observado? A continuación enunciaremos la definición formal de los Shapeley Values.


\begin{definicion}{Valores de Shapley} 
	Dado un conjunto de características $F$, el valor de Shapley ($\phi_j$) para una característica $j$ es su contribución marginal promedio a la predicción, calculada sobre todas las posibles coaliciones (subconjuntos) $S \subseteq F \setminus \{j\}$ de características. Se define como:
	\[
	\phi_j(v) = \sum_{S \subseteq F \setminus \{j\}} \frac{|S|!(|F| - |S| - 1)!}{|F|!} [v(S \cup \{j\}) - v(S)]
	\]
	
	donde $v(S)$ es la predicción del modelo utilizando únicamente el subconjunto de características $S$. La fórmula calcula el promedio ponderado del aporte de la característica $j$ a cada posible combinación de otras características.
\end{definicion}

Para dotar de un carácter más formal esta explicación, vamos a profundizar en la base axiomática de los valores de Shapley, y es que la razón por la que dichos valores son considerados la ``única'' solución justa no es gratuita.   

\begin{teorema}{Axiomas de los Valores de Shapley}
		Sea $\phi_j(v)$ el valor de Shapley asignado a la característica $j$ para una función de valor (modelo) $v$. Esta es la única asignación que cumple con:\begin{enumerate}
		\item \textbf{Eficiencia (Efficiency):} La suma de las contribuciones de todas las características debe igualar exactamente la "ganancia" total que se está repartiendo. Esto garantiza que toda la diferencia entre la predicción local y el promedio global esté completamente explicada, sin que se "pierda" o "cree" valor arbitrariamente.
		\[ \sum_{j=1}^{M} \phi_j = f(x) - E[f(X)] \]
		
		\item \textbf{Simetría (Symmetry):} Si dos características $i$ y $j$ contribuyen exactamente lo mismo a todas las posibles coaliciones de características, entonces deben recibir el mismo valor. Es decir, si $v(S \cup \{i\}) = v(S \cup \{j\})$ para todo subconjunto $S$ que no contenga a $i$ ni a $j$, entonces $\phi_i = \phi_j$.
		
		\item \textbf{Jugador Nulo (Dummy Property):} Si una característica $j$ no contribuye nada a ninguna coalición (es decir, su presencia nunca cambia la predicción), su valor debe ser cero. Si $v(S \cup \{j\}) = v(S)$ para todo $S$, entonces $\phi_j = 0$.
		
		\item \textbf{Aditividad (Additivity):} Para un juego que puede verse como la suma de dos juegos intermedios (por ejemplo, si un modelo Random Forest es la suma de sus árboles individuales), la contribución de una característica en el juego total debe ser la suma de sus contribuciones en los juegos intermedios. $\phi_j(v + w) = \phi_j(v) + \phi_j(w)$.
	\end{enumerate}
\end{teorema}

Por lo tanto es bastante importante asegurarse que los campos que tenemos correspondan al tipo que en teoría deberían de tener, por ejemplo, si contamos con un campo que sea el id del producto que más compran los clientes o incluso el identificador de cada cliente, y esos datos son un tipo de dato numérico, valdría la pena considerarlos como datos categóricos y más del tipo ordinal, esto para evitar sacar conclusiones equivocadas sobre estos tipos de datos, una forma de cambiar el tipo de dato es la que se muestra en fragmento de código \ref{EjemploFechapy}.

\begin{lstlisting}[language=Python, caption=Ejemplo de conversión de tipo de datos, label=EjemploFechapy]
	df.astype({
			'product_id': 'category',
			'customers_id': 'category'
		}
	)
\end{lstlisting}
